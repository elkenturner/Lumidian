- **Correction after Ken's review (2026-06-03):** the doc originally overstated Quora/X as "structurally crawler-blocked → uncitable." Fixed: Quora **is** Google/Bing-indexed (Googlebot allowed; only the AI bots + Google-Extended are blocked), so it's *reached via the search layer and ignored*, not unreachable. The real basis for deprioritizing is **empirical** (absent from citation studies, ~99% AIO decline), not structural. **Bigger issue Ken surfaced: citation ≠ mention.** Lumidian's score measures brand *mentions* (`brand_name in response_text`); Layer A leaned on *citation* data (which URLs were cited). A model can synthesize a brand mention from an uncited source — so "0% citations from the 5 platforms" ≠ "they don't drive mentions." - **Cross-cutting requirements for Layer B/C (Ken, 2026-06-03) — carry these into the specs:**
  1. **Strong anti-AI parameters.** Content must not read as AI-generated / must survive AI-detector scrutiny. Reframe: rules split into **two orthogonal families** — (a) *citation-drivers* (answer-first, stats, inline cites, schema, freshness — earn the mention) and (b) *human-credibility / anti-AI* (no AI tells, burstiness, voice — make it publishable). The current em-dash/banned-words/sentence-variety rules are NO-EVIDENCE for citation but legitimately serve (b) — keep them, categorize them correctly, make (b) its own independently-tunable layer.
  2. **Easy voice / guidelines integration.** A brand's or person's *voice sample or style-guidelines doc* should be a **first-class input** conditioning every draft — not the current Pro-only, bolted-on `voice.py` (`select_voice_sample`) + `BrandProfile` (tone/approved_language/what_not_to_say). Make it easy to plug in a voice/guidelines set. Synergy: writing in a real human voice IS a strong anti-AI mechanism, so (1) and (2) reinforce each other. **Layer B architecture must thread a voice/guidelines input through the pipeline from the start** (retrofitting later is expensive); the realization is mostly Layer C.
